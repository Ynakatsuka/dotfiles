# Quiz Spec

## 目的

読者が変更の因果関係を説明できるか確認する。知識量や識別子の暗記を試す問題にはしない。

## 出題

5問、各4択、単一正解とする。次の種類を組み合わせ、同じ種類を3問以上続けない。

- 挙動: 具体的な入力や状態で何が起きるか
- 因果関係: どの変更が結果を生むか
- contract: 呼び出し元との約束がどう変わるか
- edge case: 境界条件や失敗時にどうなるか
- 設計判断: 記録された判断理由やtrade-offは何か

本文の一文をそのまま選ぶ問題、file名、line番号、変数名、PR番号、人名を問う問題を作らない。説明から確認できない内容を正解にしない。

## 選択肢の品質

- 誤答は実際に起こりうる誤解から作る。冗談や明らかに無関係な選択肢を使わない。
- 正解だけを長く、具体的、断定的にしない。4択の長さ、文法、詳しさを揃える。
- 正解位置を5問で分散させる。同じ位置を続けず、一定の並びを作らない。
- 「すべて正しい」「該当なし」を使わない。
- 未実装のfallbackや仕様を、実装済みと誤認させる選択肢にしない。

## 解説

選択直後に正誤と理由を表示する。正解には根拠となる節を示す。誤答には、どの理解が違うかを短く説明する。「不正解です」だけで終わらせない。

## 実装

- 素のHTMLとインラインJavaScriptだけを使う。
- 各選択肢を`<button type="button">`にする。
- 問題ごとに独立して回答でき、選択直後にfeedbackを表示する。
- 回答済みの問題は、resetするまで再選択できないようにする。
- 正誤は色と`✓` / `✗`の両方で示す。
- 結果領域と合計点に`aria-live="polite"`を付ける。
- 5問の合計点と、全問を初期状態へ戻すbuttonを置く。
- JavaScriptが無効でも解説を読めるように、各問の解説を`<details>`にも入れる。
- 正解をCSS class、button label、`title`、初期表示のaccessibility textで漏らさない。

## 最終確認

生成後に5問を一覧で確認する。

- 正解位置に偏りがない
- 正解だけが長くない
- 誤答が具体的で、実際の誤解に対応している
- ページを理解すれば答えられる
- trick questionになっていない
